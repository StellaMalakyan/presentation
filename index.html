1. Executive Summary

The Vision

Transforming raw, unstructured ride logs into an automated spatial-analytics ecosystem that powers interactive urban-mobility insights for Jersey City (2025–2026).

Primary Core Deliverables

  • Data Pipeline: Multi-source ETL (Citi Bike + Weather API + GeoJSON).
  • Spatial Processing: Python vector overlays & PostGIS spatial joins.
  • Enterprise Storage: Dockerized PostgreSQL with spatial indexing.
  • Visual Analytics: Interactive Geospatial Engine & Tableau Dashboard.

Key Project Highlights

  • 100% Automated ingestion of multi-year monthly trip archives.
  • Spatial Integration: Mapped every trip to exact neighborhood polygons.
  • Zero Query Latency: Optimized SQL Materialized View for Tableau.

2. Business Problem & Opportunity

How does weather impact urban bike-share demand across different neighborhoods and user segments?

Operational Challenges

  • Fleet Imbalances: Stations empty out during morning commutes.
  • Unpredictable Demand: Weather fluctuations affect Casual riders differently than Daily Commuters.
  • Raw Data Complexity: Millions of raw coordinate points lack contextual neighborhood boundaries.

The Solution

A unified data engine combining micro-mobility transactions, meteorological parameters, and geographic boundaries into a single reporting layer.

3. The Core Story: Multi-Year Iterative Growth

Phase 1: Baseline 2025 Analytics

  • Processed historical baseline trips to extract fundamental ridership patterns, temporal commute waves, and coordinate boundaries.
  • Formulated data cleansing standards and spatial bounding algorithms for Jersey City.
  • Mapped early member vs. casual behavior across baseline seasonal cycles.

Phase 2: Scaling to 2026 via utils

  • Abstracted transformation logic into modular Python helper functions (utils).
  • Seamlessly ingested new 2026 dataset batches without re-writing ingestion logic.
  • Conducted year-over-year comparative analytics to identify network expansion and demand surges.

6. Pipeline Engineering & Feature Extraction

Data Hygiene via utils

  • Purges OS metadata junk (__MACOSX).
  • Drops invalid coordinate records.
  • Deduplicates rows on primary key ride_id.
  • Validates coordinate sanity checks across all ingestion runs.

Time Dimensions

  • Extracted: Year, Quarter, Month, Day of Week, Hour, and Weekend/Weekday flags.

Engineered Features

  • Ride Duration: Derived from timestamp delta in minutes.
  • Geodesic Distance: Calculated via Haversine formula (km).
  • Categorical Buckets: Short, Medium, and Long ride/distance tiers.
  • Weather Flags: Freezing, Cold, Mild, and Warm temperature buckets.

9. Containerized Spatial Database (PostGIS)

To build a production-ready system, data was loaded into a containerized PostgreSQL / PostGIS instance via Docker.

Core Database Tables

  • jersey_city: Cleaned individual trip transactions (2025–2026).
  • jersey_weather: Daily historical weather metrics.
  • jersey_city_neighborhoods: Neighborhood boundary polygons.
  • jc_2025_stations: Station locations & geometries.
-- Spatial Query Example in PostGIS
SELECT 
    s.station_name, 
    n.neighborhood
FROM jc_2025_stations s
LEFT JOIN jersey_city_neighborhoods n
    ON ST_Within(s.geometry, n.geometry);

10. High-Performance Materialized View

Instead of forcing Tableau to recalculate complex spatial joins on every filter click, a wide Materialized View was engineered at the database layer.

CREATE MATERIALIZED VIEW mv_tableau_citibike_dashboard AS
SELECT 
    r.ride_id, r.rideable_type, r.member_casual,
    r.started_at, r.ended_at, r.ride_date, r.ride_year, r.ride_month, r.ride_hour,
    r.ride_duration_minutes,
    start_n.neighborhood AS start_neighborhood,
    end_n.neighborhood AS end_neighborhood,
    w.temperature_2m_mean, w.precipitation_sum
FROM jersey_city r
LEFT JOIN jersey_weather w ON r.ride_date = w.date
LEFT JOIN jersey_city_neighborhoods start_n ON ST_Within(r.start_geom, start_n.geometry)
LEFT JOIN jersey_city_neighborhoods end_n ON ST_Within(r.end_geom, end_n.geometry);

Database Optimization Strategy

  • GIST Spatial Indexes applied on point and polygon geometries.
  • B-Tree Indexes added on filter dimensions (ride_date, member_casual, neighborhood).

13. Key Business & Operational Insights

User Persona Behavioral Split

  • Annual Members: Predictable commute spikes at 8 AM & 5 PM on weekdays. Highly resilient to rain and low temperatures.
  • Casual Riders: Peak on weekend afternoons for longer leisure trips. High elasticity to freezing weather and precipitation.

Rebalancing & Fleet Optimization

  • Net Flow Imbalance: Heavy morning net departures at residential hubs and arrivals at PATH transit stations.
  • Electric vs. Classic: Electric bikes exhibit 28% higher average distance, showing strong commuter preference.
